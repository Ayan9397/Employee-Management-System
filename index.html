OOP & Architectural Highlights

  • Polymorphism in Payroll: calculateMonthlySalary() is dynamically dispatched on SalaryCalculatable.
  • DAO Design Pattern: Repositories interface EmployeeRepository with seamless switching between JdbcEmployeeRepository and in-memory mock.
  • Relational Integrity: Supports MySQL cascading foreign keys on department_id and role_id.
  • SQL Injection Prevention: All JDBC queries utilize PreparedStatement with strongly-typed parameter bindings.

Java OOP Hierarchy 

<<interface>> Identifiable
  ↑
<<abstract>> Employee implements Identifiable, SalaryCalculatable
  ├── FullTimeEmployee
  │     - annualSalary: double
  │     - bonusPercentage: double
  │     + calculateMonthlySalary() : (annual / 12) + bonus
  │
  └── ContractEmployee
        - hourlyRate: double
        - hoursWorked: int
        - contractDurationMonths: int
        + calculateMonthlySalary() : hourlyRate * hoursWorked
Demonstrates core OOP principles: Inheritance (FullTimeEmployee extends Employee), Interface Abstraction (SalaryCalculatable), and Polymorphism where salary calculation rules differ across employee types without mutating caller logic.

MySQL Relational Schema 

TABLE: departments (
  department_id INT PRIMARY KEY AUTO_INCREMENT,
  department_name VARCHAR(100) UNIQUE NOT NULL,
  budget DECIMAL(15,2)
);

TABLE: roles (
  role_id INT PRIMARY KEY AUTO_INCREMENT,
  role_title VARCHAR(100) NOT NULL,
  min_salary DECIMAL(10,2),
  max_salary DECIMAL(10,2)
);

TABLE: employees (
  employee_id VARCHAR(20) PRIMARY KEY,
  first_name VARCHAR(50), last_name VARCHAR(50),
  email VARCHAR(100) UNIQUE,
  employee_type ENUM('FULL_TIME', 'CONTRACT'),
  department_id INT REFERENCES departments(department_id),
  role_id INT REFERENCES roles(role_id),
  annual_salary DECIMAL(12,2),
  hourly_rate DECIMAL(8,2)
);
Designed with 3NF normalization, foreign key constraints, unique indexing on email, and aggregation queries for departmental payroll reports.
